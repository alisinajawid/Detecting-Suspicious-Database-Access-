# Database Access Anomaly Detection and Audit Logs

## What database access datasets and study designs are most relevant?

### Takeaway

The closest studies use real database activity for normal-behavior profiles, but often create or inject suspicious sessions because labeled production anomalies are rare. This supports a controlled prototype, while making transparent label rules and careful claims about generalization essential.

### Cited Findings

- **Sainan Li, Qilei Yin, Guoliang Li, Qi Li, Zhuotao Liu, and Jinwei Zhu. 2022. “Unsupervised Contextual Anomaly Detection for Database Systems.” SIGMOD ’22. DOI: [10.1145/3514221.3517861](https://doi.org/10.1145/3514221.3517861).** UCAD was evaluated on real session traces from two Internet-company database applications: an online commenting service and a location service. The normal traces were split 8:2 into training and test data; the authors generated anomalous sessions because they found no public database operation-log anomaly dataset and could collect few real anomalies. They reported 354 training sessions in the commenting scenario and 3,722 in the location scenario. [Original paper](https://dbgroup.cs.tsinghua.edu.cn/ligl/papers/anomaly-detection-sigmod2022.pdf)
- **Eyal Gutflaish, Aryeh Kontorovich, Sivan Sabato, Ofer Biller, and Oded Sofer. 2019. “Temporal Anomaly Detection: Calibrating the Surprise.” AAAI 2019, pp. 3755–3762. DOI: [10.1609/aaai.v33i01.33013755](https://doi.org/10.1609/aaai.v33i01.33013755).** Their public TDA dataset contains two months of live database access records, represented as hourly user-table access matrices, with 4,702 users, 11,654 tables, and 1,488 hourly intervals. The data had no known anomalous accesses, so the experiments injected synthetic anomalies, including accesses moved to unexpected times. [AAAI paper](https://ojs.aaai.org/index.php/AAAI/article/download/4261/4139)
- **Israa Jihad Abed. 2024. “Using Machine Learning to Detect Unauthorized Access in Database’s Log Files.” Journal La Multiapp 5(6), 824–832. DOI: [10.37899/journallamultiapp.v5i6.1538](https://doi.org/10.37899/journallamultiapp.v5i6.1538).** The study used PostgreSQL log-derived data from 12 working hours at one university. Each of two constructed datasets had 34,357 normal rows and 20 anomaly rows; the anomalies were generated by changing table-use feature values. [Original paper PDF](https://newinera.com/index.php/JournalLaMultiapp/article/download/1538/1562)
- **Zhihua Wang, Hongfu Chen, Nanjing Zhang, and Youlin Hu. 2026. “Intent-Centric Unsupervised Anomaly Detection for SQL Logs in Integrated Power Grid Business Databases.” IET Communications 20, e70172. DOI: [10.1049/cmu2.70172](https://doi.org/10.1049/cmu2.70172).** The authors evaluated a 100,000-query synthetic dataset and 50,000 anonymized SQL logs from one provincial power-grid dispatch center. The semi-real set contains 49,000 normal queries and 1,000 anomalies from controlled exercises; 20% of injected anomalies were manually validated by domain experts. [Original paper PDF](https://ietresearch.onlinelibrary.wiley.com/doi/pdfdirect/10.1049/cmu2.70172)
- **Lorenzo Bossi, Elisa Bertino, and Syed Rafiul Hussain. 2017. “A System for Profiling and Monitoring Database Access Patterns by Application Programs for Anomaly Detection.” IEEE Transactions on Software Engineering 43(5), 415–431. DOI: [10.1109/TSE.2016.2598336](https://doi.org/10.1109/TSE.2016.2598336).** DetAnom was tested with PostgreSQL and generated Java test applications because the authors said they could not find a public dataset suitable for their task. The test inputs were generated pseudo-randomly. [Author-hosted paper](https://syed-rafiul-hussain.github.io/wp-content/uploads/2017/10/detanom-tse.pdf)

### Inferences

- A controlled dataset is an accepted research approach in this area, but the article should describe it as a test benchmark and explain that generated anomaly labels limit claims about real-world detection.
- A stronger evaluation would preserve a normal-only training set, generate separate held-out sessions for each of the five scenarios, and report scenario-level precision, recall, F1, and false-positive rate.

### Gaps

- Several studies do not release their operational database traces, and the synthetic or injected anomalies differ from the five scenarios planned here. Results across the papers therefore cannot be compared as if they used one common benchmark.

## Which methods and findings relate directly to the planned model comparison?

### Takeaway

Database-specific anomaly detection ranges from interpretable profile or classical outlier methods to sequence and semantic models. Isolation Forest and One-Class SVM appear as baselines in direct database studies; a 2024 paper also evaluates LOF, but its extremely small anomaly set makes its results uncertain.

### Cited Findings

- **UCAD / Trans-DAS (Li et al., 2022).** The unsupervised Transformer learns normal operation semantics from session sequences and compares each operation with its contextual intent. UCAD reports F1 scores of 0.89693 and 0.98168 in the two scenarios, about 14.9% and 30.5% above the strongest baselines as reported by the authors. Baselines included Isolation Forest and One-Class SVM. One-Class SVM reached recall 0.73408 and F1 0.83582 in scenario I; the authors report that the classical non-sequence methods missed stealthy anomalies more often. [Original paper](https://dbgroup.cs.tsinghua.edu.cn/ligl/papers/anomaly-detection-sigmod2022.pdf)
- **Temporal likelihood regression (Gutflaish et al., 2019).** TLR combines a low-rank stationary user-table model with regression that predicts expected likelihood over time, so routine temporal shifts are less likely to trigger alerts. In the experiment that moved normal activity to an unexpected time, TLR was the most successful tested method; most baselines, except SRMF, performed no better than random guessing because they did not model time dependence. [AAAI paper](https://ojs.aaai.org/index.php/AAAI/article/download/4261/4139)
- **LOF, One-Class SVM, and Isolation Forest (Abed, 2024).** The semi-supervised models were trained on normal rows. For the first constructed dataset, the paper reports per-class accuracies of 0.70 for LOF on anomalies, 0.05 for One-Class SVM, and 0.00 for Isolation Forest; on the second set these values were 0.75, 0.00, and 0.00. The models classified normal rows much more successfully than the rare anomalies. [Original paper PDF](https://newinera.com/index.php/JournalLaMultiapp/article/download/1538/1562)
- **Intent-centric SQL detection (Wang et al., 2026).** The model normalizes SQL into abstract syntax trees, infers structured query intent with a lightweight Transformer, and clusters intent plus access context with HDBSCAN. On its 50,000-query semi-real set, the full method reports AUROC 0.94, AUPRC 0.56, Precision@100 0.84, recall at 1% false-positive rate 0.69, and 2.3 false alarms per subsystem per day. In the same comparison, TF-IDF plus Isolation Forest reported AUPRC 0.19 and recall at 1% FPR 0.34; TF-IDF plus LOF reported 0.16 and 0.31; TF-IDF plus One-Class SVM reported 0.14 and 0.29. [Original paper PDF](https://ietresearch.onlinelibrary.wiley.com/doi/pdfdirect/10.1049/cmu2.70172)
- **DetAnom (Bossi et al., 2017).** This is a database-specific profile-and-check system rather than a machine-learning comparison: it builds query signatures and input constraints through concolic testing, then flags mismatches at runtime. The authors report near-accurate profiling and low runtime overhead, but do not provide a comparable precision/recall/F1 benchmark in the paper’s reported evaluation. [Author-hosted paper](https://syed-rafiul-hussain.github.io/wp-content/uploads/2017/10/detanom-tse.pdf)

### Inferences

- The proposed Isolation Forest, LOF, and One-Class SVM comparison is already present in the literature, so the project should not claim to be the first such comparison. Its contribution can be a focused, reproducible comparison on session-level audit features and five clearly defined behavioral scenarios.
- The 2024 results warn that overall or normal-class accuracy can hide near-zero anomaly detection. The project should emphasize recall, precision, F1, false-positive rate, and confusion matrices rather than accuracy alone.
- The 2026 baselines use SQL text representations and query-level context, while the planned project uses simpler session-level behavioral features. Their scores are useful context but are not directly comparable to the planned experiment.

### Gaps

- The 2019 and 2024 studies do not provide a common labeled dataset for comparing methods, and the 2024 article reports only 20 constructed anomalies per dataset. A direct numerical comparison with the planned controlled dataset would be invalid.
- The 2017 DetAnom paper addresses application-program query misuse and has a different threat model from user-session anomaly detection; it is contextual evidence, not a direct model baseline.

## What limitations and research gap should shape this project?

### Takeaway

The literature supports database audit-log anomaly detection, but dataset realism, rare labels, false alarms, time behavior, and evaluation design remain important. The defensible project gap is a narrow, transparent comparison across predefined session scenarios—not a claim that classical models have never been applied to database logs.

### Cited Findings

- **UCAD’s stated limitations (Li et al., 2022).** The authors say their approach assumes operation logs are reliable and intact, and report frequent false positives for rare normal patterns in some production environments. They suggest trusted log collection and data augmentation as possible improvements. They also note that the available abnormal-log dataset was not public and their experiments therefore included synthesized anomaly sessions. [Original paper](https://dbgroup.cs.tsinghua.edu.cn/ligl/papers/anomaly-detection-sigmod2022.pdf)
- **TLR’s evaluation limits (Gutflaish et al., 2019).** Since the datasets contained no known anomalies, the researchers injected synthetic cases. The full comparison against several matrix methods was run on downsampled 1,000-user by 1,000-object versions because those methods could not run on the full datasets within available memory. Their future work included a streaming training version. [AAAI paper](https://ojs.aaai.org/index.php/AAAI/article/download/4261/4139)
- **Abed’s limitations (2024).** The paper discusses difficulty obtaining labeled security data and calls for more work on feature selection, preprocessing, and anomaly detection. Its own evaluation uses only 20 constructed anomaly rows in each dataset and describes accuracy by class rather than providing the fuller precision/recall/FPR profile needed for imbalanced detection. [Original paper PDF](https://newinera.com/index.php/JournalLaMultiapp/article/download/1538/1562)
- **Wang et al.’s future work (2026).** The authors state that their implementation is evaluated offline in batch mode and identify temporal modeling of intent sequences and automated refinement of the intent taxonomy as future work. The semi-real source is a single provincial power-grid dispatch environment, and labels come from controlled exercise templates. [Original paper PDF](https://ietresearch.onlinelibrary.wiley.com/doi/pdfdirect/10.1049/cmu2.70172)
- **DetAnom’s limitations (Bossi et al., 2017).** The authors state that incomplete profiles can produce false negatives, query signatures may omit semantically important operators and parameter values, and concolic profile generation can be slow or grow exponentially with program branches. They tested generated applications rather than a public operational database trace. [Author-hosted paper](https://syed-rafiul-hussain.github.io/wp-content/uploads/2017/10/detanom-tse.pdf)

### Inferences

- A defensible gap statement is: *This project provides a small, reproducible comparison of Isolation Forest, LOF, and One-Class SVM on session-level features from a controlled PostgreSQL/FastAPI audit-log prototype, with held-out evaluation for five predefined access scenarios and explicit reporting of class-sensitive metrics.* It is narrower than claiming a new database anomaly-detection method.
- Check the Phase 1.3 label design before generating data. If a suspicious label is defined using a feature that is also given to the model (for example, labeling a session suspicious because estimated bytes exceed a threshold while passing that same byte total into the model), the experiment risks measuring whether the model rediscovers the rule used to create the label. Consider reporting an ablation without direct proxy features, or use scenario evidence that is independent from the model feature set.
- Separate scenario sessions in the test design and explain how thresholds were selected. Otherwise models may be evaluated on artifacts of the generator rather than on broader behavior changes.

### Gaps

- The papers do not establish universally valid thresholds for unusual query rates, extraction sizes, access hours, failed attempts, or table novelty. These must be defined for the controlled prototype and described as experimental label rules, not general security policy.
- The verified studies do not directly answer how the selected three classical models compare on one reproducible session-level dataset containing all five planned scenarios. That precise, limited comparison is the project's defensible contribution.
